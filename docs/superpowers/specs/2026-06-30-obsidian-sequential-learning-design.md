# Obsidian 顺序通关优化设计

日期：2026-06-30

## 目标

把 `0-100-quant` 的 Obsidian 笔记优化成一个按 1-33 课顺序通关的学习系统。优化重点不是重写所有课程内容，而是让入口、链接、复习路径和 Notebook 对应关系更顺，减少学习时来回找文件和点到空链接的摩擦。

  - 有些代码片段中的双中括号被 Obsidian 误识别为链接
  - README 中存在“30 个 Notebook”和实际 33 课不一致的问题
  - 当前工作区已有用户未提交改动，实施时必须避免覆盖这些改动

## 信息架构

### 入口层

`notebooks/notes/00-主页.md` 是唯一总入口，包含：

- 当前学习进度概览
- 1-33 课顺序路线表
- 每课链接、对应 Notebook、阶段归属
- 两个核心辅助入口：
  - `[[01-顺序通关路线]]`
  - `[[02-复习清单]]`

### 路线层

`01-顺序通关路线.md` 按阶段组织：

1. Python 基础：01-03
2. 数据处理：04-07
3. 可视化与统计实战：08-11
4. 金融理论与因子：12-15
5. 期权定价：16-18
6. 风控与组合优化：19-21
7. 策略开发与回测：22-28
8. ML 量化与系统化：29-33

每一课使用同一学习节奏：

1. 先读 Obsidian 笔记，建立概念地图
2. 再运行对应 Notebook，复现代码
3. 最后完成复习清单里的 3 个检查点

### 课程层

每篇课程笔记保留现有内容，在末尾统一补充：

- 上一课 / 下一课
- 对应 Notebook 文件名
- 本课复习检查点
- 相关前置或后续课程

已有结构完整的笔记只做轻量补齐；缺少导航的笔记才追加区块。

## 链接修复规则

1. 主页链接统一指向现有中文笔记文件名，例如 `[[01-Python核心语法]]`。
2. 被删除的旧英文文件链接改为对应中文文件，例如 `[[capm-beta]]` 改为 `[[12-CAPM贝塔系数]]`。
3. 文件名有连字符的笔记按实际文件名链接，例如 `[[20-Markowitz-均值方差优化]]`。
4. 对于未来主题但尚无笔记的链接，保留时要明确标注“后续专题”，或改成纯文本，避免形成无意义断链。
5. 代码中的列表切片或 DataFrame 列选择如果被误写成 `[[...]]`，改成代码格式，避免被 Obsidian 识别为链接。

## 数据流

1. 扫描 `notebooks/*.ipynb` 获取 1-33 课 Notebook 文件名。
2. 扫描 `notebooks/notes/**/*.md` 获取现有中文笔记文件名。
3. 建立课程编号到笔记、Notebook、标题的映射表。
4. 用映射表生成主页、顺序通关路线、复习清单。
5. 按映射表修复已有笔记中的主要断链和底部导航。
6. 再次扫描 Obsidian 双链，验证断链数量明显下降，主页链接全部可打开。

## 错误处理

- 如果某课找不到对应笔记，只在总入口中标注“待补笔记”，不凭空生成主体内容。
- 如果某个文件已有用户未提交改动，只做必要的追加和链接修复，不覆盖整篇内容。
- 如果自动检查发现仍有断链，区分三类处理：
  - 旧命名断链：直接修复
  - 未来主题断链：改成纯文本或标注后续
  - 代码误识别断链：改成代码格式
